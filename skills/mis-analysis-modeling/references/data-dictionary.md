# Complete Data Dictionary

## 正式源原则

数据字典是DFD的文字定义层。完整字典是正式源，报告中的选用卡片、汇总表和截图是派生产物，不能反向删减正式源。

## 六类字典

### 外部实体字典

最低字段：

- 卡片编号；
- DFD编号；
- 名称；
- 边界说明；
- 输入系统的数据流；
- 接收系统的数据流。

### 处理字典

最低字段：

- 卡片编号；
- DFD处理编号；
- 名称；
- 输入；
- 读取/写入存储；
- 输出；
- 触发条件；
- 加工逻辑；
- 异常处理；
- 频率或时机。

第三层处理必须独立定义，或在模型中显式声明它由哪张父处理卡片完整覆盖。不能一边声称“覆盖全部处理”，一边省略实际图中的细化处理。

### 数据流字典

最低字段：

- 卡片编号；
- 稳定逻辑ID；
- 可见名称；
- 简述；
- 组成；
- 来源；
- 去向；
- 频率或峰值流量。

每条实际命名边必须命中字典，或声明为某父数据流的细化流。

### 数据存储字典

最低字段：

- 卡片编号；
- DFD编号；
- 名称；
- 组成；
- 逻辑关键字；
- 读取处理；
- 写入处理；
- 规模、保留或访问说明。

逻辑数据存储不是物理数据库表，可以在设计阶段拆为多张表。

### 数据结构字典

最低字段：

- 卡片编号；
- 结构编号；
- 名称；
- 简述；
- 子结构或数据项组成。

### 数据项字典

最低字段：

- 卡片编号；
- 项目编号；
- 名称和别名；
- 业务含义；
- 逻辑类型；
- 长度或精度；
- 值域；
- 是否必填；
- 敏感性或校验规则。

系统分析阶段优先表达逻辑类型。PostgreSQL、MySQL、Prisma等物理类型在数据库设计阶段映射，不应混用后再声称完全一致。

## 字段闭包

所有数据流、存储和结构的“组成”最终必须落到已定义的数据项：

```text
数据流 → 数据结构 → 数据项
数据存储 → 数据结构 → 数据项
```

同义词需要显式别名，例如“价格”映射到“商品价格”，不能仅靠人工猜测。

## 状态码

每个状态集必须定义：

- 状态集ID；
- 业务对象；
- 每个代码和值的唯一语义；
- 允许转换；
- 触发者；
- 终态；
- 异常或回退规则。

同一个数字在字典、Schema、服务常量和Seed中含义不同属于阻断性错误。

## 节选规则

报告需要节选时：

1. 生成独立派生文件；
2. 明确注明“本文仅节选”；
3. 附完整源位置和各类总数；
4. 覆盖主要外部实体、主处理、逻辑存储、主键、金额和状态；
5. 数量由正式源实时计算，不手写估数；
6. 节选不得改变编号、名称和值域。
