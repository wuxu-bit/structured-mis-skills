# Traceability and Validation Gates

## 追踪链

每个核心功能应形成：

```text
需求 R
→ 业务闭环 B
→ TFD 图与节点
→ DFD 处理/数据流/存储
→ 数据字典卡片
→ 状态和数据项
→ 后续模块/物理表
```

每个箭头都需要显式映射，不允许只写“基本一致”。

## Gate A：需求覆盖

- `must`需求必须映射到业务闭环或明确排除项。
- 一个闭环可以覆盖多个需求。
- 未映射需求阻止最终交付。

## Gate B：TFD完整性

- 图题所列阶段实际存在。
- 每个处理有输入和输出。
- 正常、关键异常和状态变化形成闭环。
- 单据与长期存档没有混用。
- 图中节点都能回溯到基线。

## Gate C：DFD结构

- 顶层边界完整。
- 第一层覆盖顶层边界。
- 子图只展开声明的父处理。
- 每个处理一入一出。
- 禁止非法直连。
- 数据流有稳定ID和名称。

## Gate D：父子平衡

机器可读模型中，每张DFD必须声明：

- `id`和`level`；
- `processIds`与`storeIds`；
- 子图的`parentDiagramId`和`parentProcessId`；
- 整图`boundaryFlows`中的`flowId`、外部`endpointId`、`direction`和接收/发出该流的`processId`；
- 每个处理独立的`processBoundaries`，用于后续只展开该处理时比较局部边界。

非顶层DFD必须声明`parentDiagramId`和`parentProcessId`，层级必须恰好增加1。父流被拆分时，在`mappings.dataFlowRefinements`记录`parentFlowId`和`childFlowIds`。未声明的名称近似不视为合法细化。

对父处理的每条输入输出记录：

| 父流 | 端点 | 方向 | 子图对应 | 结果 | 说明 |
|---|---|---|---|---|---|

只有 `exact` 和具有明确拆分规则的 `refined` 可以通过。

## Gate E：字典闭包

- 图中实体、处理、流和存储全部命中字典。
- 数据结构和数据项组成闭包。
- 卡片编号唯一、连续或有明确保留原因。
- 图上编号和卡片编号使用不同命名空间。

## Gate F：跨阶段一致性

- 状态名称和值域唯一。
- DFD逻辑存储与数据库设计建立映射。
- 实现偏差单独记录。
- 报告文字不覆盖机器可读事实。

## 严重度

| 等级 | 示例 | 处理 |
|---|---|---|
| error | 边界流缺失、状态码冲突、悬空边、字典缺项 | 阻止交付 |
| warning | 合法副本未注释、样式不统一、跨域只读未说明 | 记录并确认 |
| info | 报告节选、可选布局优化 | 不阻止交付 |

## 审计报告

报告必须区分：

- 规划模型；
- 当前图源事实；
- 字典事实；
- 实现事实；
- 冲突；
- 建议修正；
- 尚未验证项。

不要把“文档声称”改写成“已经验证”。
