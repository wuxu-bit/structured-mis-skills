# Prisma Workflow

## 职责

- `schema.prisma`定义模型、字段、关系、约束和映射。
- Prisma CLI格式化、校验、生成Client并管理迁移。
- 迁移SQL是必须审查的数据库变更证据。
- DBHub不替代以上任何职责。

## 静态阶段

在修改数据库前：

1. 核对数据源provider。
2. 格式化Schema。
3. 校验Schema。
4. 比对逻辑到物理映射。
5. 检查默认值、可空性、唯一约束、索引和删除动作。

具体命令取决于项目锁定的Prisma版本和包管理器。使用项目本地依赖，不临时下载`latest`。

## 迁移阶段

生成迁移前说明：

- 当前环境；
- 目标数据库；
- 预期表和字段变化；
- 是否存在数据迁移；
- 是否可能丢失数据；
- 回滚或修复策略。

迁移生成后审查：

- `DROP`、重建表和危险类型转换；
- 非空列是否有安全默认值或回填步骤；
- 外键动作；
- 索引是否重复或缺失；
- 表、列命名是否匹配映射；
- 迁移顺序和事务边界；
- 大表锁表风险。

## 环境边界

- 开发环境可生成迁移。
- CI可校验迁移和Schema漂移。
- 部署环境只应用已审查迁移。
- 生产环境禁止reset和开发式迁移。
- 无Schema变化时不要为“看起来完整”制造空迁移。

## 证据

保存Schema校验结果、迁移名称、SQL审查结论和应用结果。不要保存真实连接串。
