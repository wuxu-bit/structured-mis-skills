# Analysis-to-Implementation Drift

## 对比层次

逐层比较：

1. DFD逻辑存储和读写处理；
2. 数据结构、数据项和状态码；
3. 数据库设计；
4. Prisma Schema；
5. 迁移SQL；
6. 运行时服务常量和事务；
7. Seed；
8. 实际数据库。

## 差异分类

| 分类 | 含义 | 示例 |
|---|---|---|
| accepted-split | 合理的逻辑到物理拆分 | 用户档案拆为用户和认证表 |
| defect | 同一语义实现错误 | 状态码3在字典与服务中含义不同 |
| simplification | 有意缩小原型范围 | 外部支付改为模拟模块 |
| deferred | 设计存在但尚未实现 | 实时通知待实现 |
| stale-document | 文档已过时 | 文档写MySQL，当前实现PostgreSQL |
| unverified | 缺少运行证据 | 未查询实际索引 |

## 差异记录

每条包含：

- ID；
- 分类；
- 受影响需求和元素；
- 分析事实；
- 设计事实；
- 实现事实；
- 证据路径；
- 影响；
- 决策；
- 负责人和状态。

## 判定原则

- 合理拆分不是缺陷，但必须可追踪。
- 文档声称与实现不同，以实现事实记录当前状态，同时修正文档或标记过时。
- 未实现功能不能写成已实现。
- 没有DBHub或测试输出时只能写“计划验证”，不能写“验证通过”。
- Schema一致不代表业务事务一致；关键状态联动仍需服务和事务审查。
